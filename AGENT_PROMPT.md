## 1. Desired End-User API

After your changes, users should write code like this:

```rust
use text_search::{IndexWriter, IndexReader, SearchQuery, Indexed, Indexable};

#[derive(Indexed, Clone, Debug)]
pub struct Book {
    #[text_search(id)]
    pub id: i32,
    #[text_search(indexed_text, stored)]
    pub name: String,
    #[text_search(indexed_string, stored)]
    pub author: String,
    #[text_search(indexed_text, stored)]
    pub description: String,
    pub published_on: i32,
    #[text_search(indexed_string, stored)]
    pub tags: Vec<String>,
}

// --- Searching ---
let query = SearchQuery::new(Book::name, "Rust")
    .with_filter(
        Book::author.eq("Bogdan")
            .and(Book::tags.eq("xyz"))
    )
    .page(1)
    .per_page(10);

let result = index_reader.search(&query)?;
let result = index_reader.fuzzy_search(&query)?;
let result = index_reader.regex_search(&query)?;
let result = index_reader.hybrid_search(&query)?;

// Filter-only operators (for numeric/date fields):
Book::published_on.gt(2020)
Book::published_on.ge(2020)
Book::published_on.lt(2025)
Book::published_on.le(2025)
Book::published_on.ne(2022)

// Combining with .or():
Book::author.eq("Bogdan").or(Book::author.eq("Tim"))
```

Key points:
- `SearchQuery::new(Book::name, "Rust")` — first arg is a `FieldRef` (the field to full-text search on), second is the query string.
- `.with_filter(...)` — accepts a `Filter` built from `FieldRef` comparison methods.
- `.page(n)` / `.per_page(n)` — pagination, defaults to page=1, per_page=10.
- `Book::name`, `Book::author`, etc. are **associated constants** of type `FieldRef` generated by the derive macro.

### 4.3 Rewrite `filter_query`

Replace:
```rust
fn filter_query(&self, filters: HashMap<&str, &str>, query: Box<dyn Query>) -> Box<dyn Query>
```
with:
```rust
fn apply_filter(&self, filter: Option<&Filter>, search_query: Box<dyn Query>) -> Box<dyn Query>
```

This recursively converts a `Filter` tree into tantivy queries:

- **`Filter::Condition { field_name, op: Eq, value: FilterValue::Str(s) }`**:
  Use `QueryParser::for_index` with the quoted string (existing approach): `format!("\"{}\"", s)`.

- **`Filter::Condition { field_name, op: Eq, value }` (non-string)**:
  Use `tantivy::query::TermQuery::new(value.to_term(field), IndexRecordOption::Basic)`.

- **`Filter::Condition { field_name, op: Ne, value }`**:
  Wrap the Eq query in a `BooleanQuery` with `(Occur::MustNot, eq_query), (Occur::Must, Box::new(AllQuery))`.

- **`Filter::Condition { field_name, op: Gt|Ge|Lt|Le, value }`**:
  Use `tantivy::query::RangeQuery`. Build it with the appropriate `Bound::Included` / `Bound::Excluded` / `Bound::Unbounded` using the Term from `value.to_term(field)`.
  - `Gt(v)`: left = `Bound::Excluded(term)`, right = `Bound::Unbounded`
  - `Ge(v)`: left = `Bound::Included(term)`, right = `Bound::Unbounded`
  - `Lt(v)`: left = `Bound::Unbounded`, right = `Bound::Excluded(term)`
  - `Le(v)`: left = `Bound::Unbounded`, right = `Bound::Included(term)`

- **`Filter::And(filters)`**:
  Convert each to a query, combine with `BooleanQuery` using `Occur::Must` for each.

- **`Filter::Or(filters)`**:
  Convert each to a query, combine with `BooleanQuery` using `Occur::Should` for each.

Delete the old `new_boolean_query_filters` method.

### `text-search-derive/src/lib.rs`
```rust
mod context;
mod field_info;
mod indexable;
mod struct_info;
use context::Ctxt;
use field_info::get_field_info;

use proc_macro::TokenStream;
use syn::{Data, DeriveInput, Fields, parse_macro_input};

#[proc_macro_derive(Indexed, attributes(text_search))]
pub fn text_search_macro(input: TokenStream) -> TokenStream {
    let ctxt = Ctxt::new();
    let input = parse_macro_input!(input as DeriveInput);
    let name = input.ident;

    let fields = if let Data::Struct(data) = input.data {
        if let Fields::Named(fields) = data.fields {
            fields
        } else {
            panic!("Only named fields are supported.");
        }
    } else {
        panic!("Only structs are supported.");
    };

    let mut derive_fields: Vec<field_info::DeriveFieldInfo> = Vec::new();
    for field in fields.named.iter() {
        derive_fields.push(get_field_info(&ctxt, field));
    }

    let impl_indexable = indexable::impl_indexable_token(
        name.clone(),
        text_search_core::StructInfo::new(name.to_string()),
        &derive_fields,
    );

    impl_indexable.into()
}
```

## Constraints

- **Edition**: Rust 2024 (`edition = "2024"` in all Cargo.toml files).
- **Do NOT modify**: `IndexField` trait, its impls, `IndexFieldSingle`, `IndexFieldVec`, `Indexable` trait signature, `FieldInfo`, `StructInfo`, `IndexType`, `FieldType`, `Symbol`.
- **tantivy version**: 0.22.0 (already in deps).
- **darling version**: Use `0.20.x` (compatible with syn 2.x).
- All `FieldRef::new` must be `const fn` so it can be used in `const` associated items.
- The `SearchQuery`, `Filter`, `FieldRef`, `FilterValue`, `FilterOp` types live in `text-search-core` and are re-exported from `text-search`.
- Keep `symbol.rs` as-is — darling replaces the need for manual symbol matching in the derive, but symbol.rs itself can stay (it's harmless).
- Make sure `cargo build`, `cargo test`, and all three examples compile and run.
